comment: the valid stack starts at 0x7c00 because that was initial value assigned to esp at bootasm.S. 
the first valid stack value is 0x00007c4d. that is the return value generated by the call to bootmain
the stack is then populated in bootmain. in order, ebp, edi, esi, ebx are pushed onto the stack. 
they are all zero. they are the callee-saved register. then, the function allocate stack for local variables.
there are four of them, so 0x10 bytes are allocated (each one word). however, when looking at the printed stack,
we can clearly see that the top most one is the return address of the function call to entry, which only leaves us 3 local variables
there are some trickery going on with the gcc O2 optimization. I believe the function variable entry() is never allocated on the stack
instead, it is only hardcoded in the instruction. 
so the remaining three slots are just the local variables except entry.
I did not figure out exactly which variable belong to the three remaining slots. but to do so should be fairly easy.
also, it is noted that in this asm the parameters of a function is stored in the stack (in some asm it is only stored in the register)
so after each function call the stack needs also to be cleared. hence `sub $0x10, %esp`.
even though there is only three parameters, 0x10 instead of 0xc is used is probably for aligning purposes. not exactly sure. but not too related to the topic
